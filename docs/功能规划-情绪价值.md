# 情绪化功能规划 · v1.1 → v1.2

> **版本号已重排（2026-11-21）**：首次对外发布定为 **v1.0**，把原计划的 P0 全部装进去了。
> 因此原「v1.2 陪伴」顺延为 **v1.1 时光**，原「v1.3 长期」顺延为 **v1.2 流年**。
> 下文标题已按新编号改写，功能编号（F1~F14）保持不变。

> 目标：把「一块很好看但很安静的工时牌」变成「一天里会给你几个小瞬间的桌面伙伴」。
> 前提：不加负担、不改工具属性、不为情绪牺牲可读性。

## 版本主题

**取名是三件事里的最后一件。** 顺序固定：

1. **先定主题**——这一版想让用户多出一个什么感受？（一句话，不带名字）
2. **再拆功能**——为这个感受具体做哪几件事，各自改哪里、要多少数据。
3. **最后命名**——回头看一眼做完的东西像什么，再给它一个名字。

倒过来做会出问题：先有一个漂亮的词，再硬找事去填它，填出来的一定是偏的。
这个项目前面几轮命名翻来覆去，就是因为把第 3 步提到了第 1 步。

| 版本 | 主题（先） | 这一版实际做了什么（中） | 名字（后） |
| --- | --- | --- | --- |
| **v1.0** | 让这块地第一次有反应 | 木牌与两个选项、5 秒烟花、里程碑金色百分比、时段问候、鸟群、月亮、草地道具、天气、午休 z、加班入夜 | **初火**——第一根火把点亮（x.0 大版本，用重名） |
| **v1.1** | 让它开始记事 | 累计天数与工时（F8）、今日结算（F9）、一周视图（F10）、吐槽两句（F15）、累计里程碑（F16） | **时光**——日与周的刻度（x.N 小版本，用轻名）✅ |
| **v1.2** | 让它有年岁 | 月度地图（F11）、季节主题（F12）、轻互动（F13）、音效（F14） | **流年**——月与年的流转 |

> **命名分两档，跟版本分量走：**
> **x.0（大版本）用重名**——意象 + 文言，一个名字开一个世界，如 v1.0「初火」；
> **x.N（小版本）用轻名**——两字日常语词，一版只抬一格，如 v1.1「时光」、v1.2「流年」。
> 小版本硬塞重名字会头重脚轻，大版本用轻名字又撑不住场面。
>
> **v2.0 的名字现在不取。** 先想清楚 2.0 要做成什么样的事，功能拆完了再回头看它像什么。
> 「岁华拾遗」「四时纪行」这些只是候选词，放在这里备忘，不作数——对不上就废掉。
>
> **写法统一**：`MC 工时牌 v1.1：时光`。版本号后面用**全角冒号**接主题名——
> 用空格会和前面的软件名糊成一片，冒号一眼就能分出「哪个版本」和「叫什么」。
> GitHub Release 标题、更新文档、以后任何地方都按这个写。

## 一、先给结论

现状是**美术 9 分、情绪 5 分**。它把「还有多久下班」这件事做到了极致，但**一天里只服务了一个情绪时刻**——临近下班的期待。而上班族真正难熬的是四个时刻：

| 时间 | 真实心理 | 现在被服务了吗 |
|---|---|---|
| 09:00 刚坐下 | 抗拒、拖延、不想开始 | ❌ 只有倒计时默默启动 |
| 12:00 午休 | 松一口气 | 🟡 有「休息中」，但画面是静止的 |
| 15:00–16:00 低谷 | 疲惫、走神、怀疑人生 | ❌ 完全空白，且倒计时数字放大焦虑 |
| 17:40 临近下班 | 躁动、期待 | ✅ 倒计时最擅长这里 |
| 18:00 之后 | 沮丧、被剥夺感 | 🟡 只有「已加班 XX 分钟」，越看越丧 |

**核心问题不是缺功能，是缺"事件"。** 现在的界面是一条连续的渐变（草在长、天在变色），没有一个是"发生"的。人记得住的从来不是渐变，是事件。

所以三批功能的逻辑是：

1. ~~**造峰值**~~ ✅ **已随 v1.0 交付**——「开工 / 达成 / 下班」都做成了看得见的事件。
2. **v1.1 时光**——它开始记事：累计天数与工时、今日结算、一周视图、随手小记、累计里程碑，日与周的刻度就此落定。
   （原计划的「有活物、有天气」已在 v1.0 做完，见 F6 / F7。）
3. **v1.2 流年**——把时间摊开给你看：月度地图、季节更替、轻互动、音效。

## 二、现有功能 × 场景契合度盘点

| 功能 | 它实际解决的问题 | 情绪作用 | 契合度 | 短板 |
|---|---|---|---|---|
| 无边框置顶 + 右键穿透 | 不挡工作、不抢焦点 | 无感（这是及格线） | ★★★★★ | 无 |
| 倒计时数字 | 精确知道还剩多久 | 单向：只放大焦虑，不给安慰 | ★★★★ | 越接近下班越躁，越超时越丧 |
| 草地生长条 | 把"熬时间"变成"看草长" | 掌控感、进度感 | ★★★★★ | 纯渐变，没有可记忆的瞬间 |
| 天空 / 云 / 天色 | 让静止的界面"活着" | 氛围、时间流逝感 | ★★★★ | 几小时才被注意到一次 |
| 花海 + 每天三种主花 | 每天不一样 | 新鲜感 | ★★★★ | 变化太静，用户不知道"今天不一样" |
| 每日一句（481 句） | 一天一个情绪触点 | 被理解、被点醒 | ★★★★ | 一天只有一次，读完即止 |
| 草皮卷 | 把前沿拟物化 | 细节彩蛋 | ★★★ | 太细，多数人不会注意到 |
| 累计加班 / 最近记录 | 记账 | **负向**：数字越大越沮丧 | ★★ | 只有加班，没有"正常下班"的正向表达 |
| 三档尺寸 / 托盘 / 自启 | 工具性适配 | 无感 | ★★★★ | 无 |

**盘出来的三个空洞：**

- **空洞 A：没有峰值。** 全天的情绪是一条平线，没有任何"哇"的一秒。
- **空洞 B：没有活物。** 风景很美，但没有人、没有动物、没有回应——它是海报，不是伙伴。
- **空洞 C：没有正向叙事。** 唯一的长期数据是加班时长。也就是说，这个产品**只在你不幸的时候记录你**。

## 三、设计原则（写代码前先立规矩）

1. **一秒可读**：所有新元素必须在"余光扫一眼"里成立，不做需要阅读的文本流。
2. **不抢注意力**：单次动效 ≤ 3 秒，一天 ≤ 5 次；默认零声音；全部可关。
3. **环境叙事优先于文案**：能用天色/花/生物表达的就不写字，文字只用来点题。
4. **每天不同，但不能失真**：一律按 `day.toordinal()` 播种（沿用现有 `seed_day`），同一天刷新画面完全固定。
5. **不做第二件事**：它只管"时间"，不做待办、不做番茄钟、不做喝水提醒。

## 四、功能清单（按优先级）

### P0 · 已随 v1.0 交付（原计划 v1.1 峰值时刻）

#### F1 下班那一刻：草卷滚出画面 + 木牌升起

> ✅ **v1.0 已实现**：木牌 + 「回家 / 再干会儿」+ 5 秒烟花彩纸；25 秒无操作自动询问。
- **核心作用**：达成 9 小时整的一瞬间，草皮卷从右侧滚出画面，天空放一小簇像素烟花，一块木牌从下方升起来写「下班」。
- **目标情绪**：**释放感 / 完成感**。把"熬完"变成"干完了"。这是全天唯一允许"夸张一点"的 2.6 秒。
- **实现思路**：
  - `widget._tick()` 里记 `self._prev_state`，检测 `WORKING → OVERTIME`（或 `progress` 首次到 1.0）的跨越，置 `self._fx = ("done", t0)`。
  - 复用现成的 40ms 临时定时器机制（`_anim_step` / `_animating`），只在这 2.6 秒提到 25fps，结束自动回落 1fps。
  - `theme.draw_done_fx(p, ...)`：木牌用现成的 `texture("wood")` + `draw_cjk_vcenter`，烟花是 3 帧 8×8 像素爆点（白→黄→橙→暗红，逐帧掉格）。
  - 触发一次后当天不再触发（`store` 记 `celebrated:<date>`）。
- **风险/开关**：`ui.fx.celebrate`，默认开；怕吵的人可关（关掉就只是数字变化）。

#### F2 里程碑：花瓣爆开

> ✅ **v1.0 已实现**，但**换了做法**：花瓣在这个尺寸读不出来，改为金色百分比 + 草皮卷上颠一帧。
- **核心作用**：进度跨过 25% / 50% / 75% / 90% 时，前沿那卷草皮旁边爆开一小簇花瓣（6–10 个像素点，飞 12 帧落地消失），同时脚下的百分比重描一次。
- **目标情绪**：**阶段感 / 被奖励**。4 小时、6 小时这种"看不见的墙"变成 4 个可以数的小胜利。
- **实现思路**：`_tick()` 里把 `progress` 和上次记录比，跨阈值就 `theme.draw_petal_burst(p, x, gy, seed)`；粒子颜色取当天主花（已有主花逻辑）；去重存 `self._hit = {0.25, 0.5, ...}`，跨重启用 store 的当日字段。
- **风险/开关**：`ui.fx.milestone`，默认开。粒子必须**小**——1 单位 = 2px，超过 8 个就成噪点。

#### F3 时段问候：header 换成会说话的一句

> ✅ **v1.0 已实现**：按时段分桶（每桶 9~15 句），点一下能换下一句，跨天自动换。
- **核心作用**：顶部「工作计时」四个字按状态和时段变：早上「开工了」、午后低谷「最难的一段」、17:30 后「快熬到头」、超时「该回家了」、周末「今天不用上班」。
- **目标情绪**：**被理解**。这是最便宜的情绪设计——同一个位置，一句话就让人觉得"它知道我现在什么感受"。
- **实现思路**：
  - `quotes.py` 加 `greeting(state, now, progress) -> str`，按时段表分桶，每桶 6–8 个变体，`day.toordinal() % len()` 取（和每日一句同一套确定性手法）。
  - 渲染位置复用 `L["title"]`，小档也有这个位置（正好填住 `title_x` 之后的空当）。
  - **硬约束**：≤ 6 个汉字，字号 11 单位，超了会被进度条挤掉。
- **风险/开关**：`ui.fx.greeting`。文案必须"短且不油"，宁可朴素。

#### F4 加班入夜：萤火虫 + 卷子变慢

> ✅ **v1.0 已实现**，但**换了做法**：萤火虫（单点光）读不出来，改为下班后天色继续向深夜走，日落后挂月亮。
- **核心作用**：进入 `ST_OVERTIME` 后，天色继续往深夜走（在 `_visual_hour` 上叠一个 0.8 小时的偏移），草地上浮出 3–5 个忽明忽暗的萤火虫，草皮卷的待机转速降到 40%。
- **目标情绪**：**体谅 / 一点温柔的催促**。不用文字说"早点回家"，让环境替你天黑。
- **实现思路**：`_visual_hour()` 加 OT 偏移；`theme.draw_fireflies(p, ..., secs, seed_day)`，每个萤火虫是单格 2×2 像素，亮度按 `sin(secs * k + phase)` 在两级之间跳（不做渐变，保持像素感）；`sod_roll_idle_speed` 读时乘系数。
- **风险/开关**：`ui.fx.firefly`。

#### F5 午休小剧场：云遮日 + 花合上 + Zzz

> 🟡 **v1.0 部分实现**：花收成花苞 + 草地右侧飘三个 z。「云遮日」没做——这个尺寸看不出云在遮挡。
- **核心作用**：12:00–13:00 时，太阳挪到正中偏右，一朵云慢慢飘到太阳前面，花冠收拢一格，画面右下浮起三个上下跳的「z」。
- **目标情绪**：**松弛 / 被允许休息**。让"午休"从一行文字变成一段可以看的画面。
- **实现思路**：`state == ST_LUNCH` 时走 `theme.draw_lunch_fx`；花高在 `_draw_flower_field` 里乘 0.75 并跳过花冠；Zzz 用 `draw_cjk_vcenter` 画 3 个字母，透明度按秒呼吸（两档跳变）。
- **风险/开关**：`ui.fx.lunch`。

### P1 · v1.1 时光（需要少量新数据）

#### F6 路过的小生物

> 🟡 **v1.0 部分实现**：原版猪/牛/羊/鸡试过三版，太大且不像，已完整回退。改成了**鸟群**（三种队形，一天 2~3 次）+ **草地道具**（栅栏 / 干草堆 / 石堆，按 19% / 53% / 84% 出现）。
- **核心作用**：一天里 2–3 次，一只像素蜜蜂 / 鸡 / 猫从草地一端走到另一端（约 12 秒），不交互、不打断。
- **目标情绪**：**惊喜 / 陪伴**。这是投入产出比最高的一项：几帧动画，换一整天的"今天它会不会来"。
- **实现思路**：`day.toordinal()` 播种出 2–3 个出现时刻（如 10:20、15:40），`_content()` 里判断 `now` 落在窗口内就传 `critter=(kind, x_unit, frame)` 给 `draw_meadow_bar`；走到头就消失，过了时段不补。
- **风险/开关**：`ui.fx.critter`（0 = 关，1–3 = 每天几只）。**必须稀**，一天十次就变成干扰。

#### F7 天气系统

> ✅ **v1.0 已实现**：晴（62%）/ 阴（24%）/ 小雨 / 大雨，按日期播种；雨天 8fps 小雨丝、大雨斜落长雨丝；右键可关。
- **核心作用**：按日期播种晴（60%）/ 多云（20%）/ 小雨（12%）/ 薄雾（8%）；雨天有 2 帧雨丝、草地加湿、卷子拖泥；雾天在地平线压一条半透明灰带。
- **目标情绪**：**真实感 / 共情**。"今天下雨"和窗外的天气对上时，那种"它跟我活在同一个世界"的感觉非常强。
- **实现思路**：`weather_of(day)` 纯函数（哈希 `toordinal()` 取模，加权），不存状态；`_draw_sky` 里插滤镜，`palette_at` 里乘饱和度；雨丝在 `draw_meadow_bar` 最后画，1 单位宽、2 单位长，随机偏移但按秒只走 1 格。
- **风险/开关**：`ui.fx.weather`。不要做雷电/闪白，会吓人且费电。

#### F8 累计：一共干了多少天、多少小时

> ✅ **v1.1 已实现**（口径已改）。原设计是「连续准点 → 金花」，落地时换掉了。
- **为什么改口径**：这是弹性制工具——登记上班时间，按在岗时长往后推下班，配置里**没有标准上班时刻**。勾了「记住」的用户每天自动登记，人人都是准点，这个指标自证为空。所以不统计"连续"，统计**累计**。
- **累计上班天数** = 保留期内的登记天数 + 已修剪归档的天数（`days_archived`）。修剪时必须记一笔，否则「用了多少天」会随时间倒退。
- **累计有效工时** = 标准在岗时长 × 天数 + 累计加班。不加班的日子不落 `ledger`，没法逐日累加，这是唯一可行的推算；改过工时制后历史按新值重算，可接受。
- **呈现位置**：不单开面板，作为「今日结算」（F9）的顶部大字——「累计 37 天 / 共 312 小时 15 分」。
- **放弃的部分**：金花与 streak 链路。断链会给人扣分感，而「累计」只增不减。

#### F9 今日结算（原「今天这块地」）

> ✅ **v1.1 已实现**：右键 →「今日结算…」，`DayDialog`（208×152）。
- **核心作用**：右键加一项，弹一个像素面板，**只讲工作本身**：

  | 行 | 实际实现 |
  | --- | --- |
  | 顶部 | 累计 N 天 · 共 X 小时 Y 分（F8） |
  | 在岗时段 | `08:50 → 17:50` |
  | 有效工时 | 跨度 − 午休重叠 |
  | 今日加班 | `32 分钟`——**只有真加班才出现**，没有就不占一行 |
  | 常在 | `09:00 前后到岗`（最近 30 天到岗时间的中位数，F16） |
  | 底部短评 | `今天没吃亏`（过了下班点才出，见下） |

- **只留三行数据**（在岗 / 有效 / 常在），最多四行：
  - 不列「本周累计」——一周面板里有合计，这里再写一遍只是把面板塞满。
  - 不列「对比昨天」——短评已经说了"比昨天早走/晚走"，同一件事说两遍。
  - 六行字挤在一起读不过来，删到三行反而每行都看得清。

- **三条实现约定**：
  1. **对比昨天只在今天过了下班点后才出现**。上班中间拿半天比人家一整天，永远显示负数——那是误导，不是激励。
  2. **短评同理，上班中间不出**。那时候说什么都像催促。
  3. 数据不全的行直接不出现，不显示 `0` 或 `—`。
- **短评规则**（纯 if-else，不接大模型）：加班 ≥60 分「今天多干了不少，早点睡」；加班 >0「加了会儿，不算多」；比昨天早走 ≥30 分「比昨天早走，挺好」；晚走 ≥30 分「比昨天晚走，明天早点」；其余「今天没吃亏」。
- **高度按内容算**：`H_UNITS = 78 + 10×行数 + 短评 + 小记`，没有内容就不留空行。
- **明确不写**：铺了几格草、开了几朵花——**那是画面说的话，不是工作说的话**。
- **目标情绪**：**被看见 / 收尾仪式**。想知道的是"我今天到底干了多久、比平时好还是差"。

#### F10 一周（原「一周五块田」）

> ✅ **v1.1 已实现**：右键 →「一周…」，`WeekDialog`（208×172）。
- **核心作用**：七天各一根柱子，**柱高 = 当天有效工时**；超出标准工时的天用亮色，今天柱顶加高光，没登记的天只留一条底线。
- **顶部三行**：`本周` / `共 54 小时 45 分` / `比上周多 9 小时 45 分钟`。差值在 5 分钟以内说「和上周差不多」，不显示「多 0 分钟」。
- **为什么不用数字**：这个尺寸下七行数字读起来费劲，柱子的长短一眼分得出来。具体数值在 F9 里看。
- **实现**：`store.week_minutes()` 返回周一起头的七天，`None` 表示那天没登记；`week_total()` 算任意一周合计。
- **目标情绪**：**时间有形状**，但形状由工时决定，不是花朵数量。
- **不复用草地绘制**：草地是单日叙事，塞进周视图会糊。

#### F15 吐槽两句（原「随手小记」）

> 菜单入口叫「吐槽两句…」。按钮是「取消 / 确定」，不是「清空 / 记住」——
> 清空读起来像"要把我写的删掉"，而人想表达的是"算了不写了"。
> 输入框提示一天换一句（`NOTE_HINTS`），第一句是用户原话：「烦心事都写在这里，本宝宝帮你记住！」

> ✅ **v1.1 已实现**：右键 →「记一句…」，`NoteDialog`（208×104，单行输入，上限 60 字）。
- **核心作用**：用户自己想说的话，不必和工作有关——「会开完了，人麻了」。
- **为什么值得做**：前面几项都是软件算出来的，这一项是用户写的。数据能算出工时，算不出今天为什么烦。
- **存储**：`data.json` 的 `notes: {日期: 文本}`，和其他桶一起按 90 天修剪。清空 = 存空串 = 删键。
- **呈现**：「今日结算」底部一行 `记：……`（超过 22 字截断加省略号）。和工作数据不是一类，所以另起一行、用暗色。
- **不做的事**：不弹提醒、不做历史列表、不导出。它就是个便签，越轻越好。

#### F16 累计里程碑

> ✅ **v1.1 已实现**：累计满 10 / 50 / 100 / 365 天，或累计满 100 / 300 / 500 / 1000 小时时，主界面飘一句 + 金色特效 1.4 秒。
- **核心作用**：把「累计」这个数字变成一次事件，而不是永远躺在面板里。
- **只响一次**：达成的里程碑记在 `data.json` 的 `milestones` 里（如 `d10` / `h100`），重装、重启、换电脑都不会重复庆祝。
- **首次运行静默播种**：升级到 v1.1 的老用户可能早就过了 10 天，第一次打开不补庆祝——过去的事不是刚发生的事。这和进度条里程碑（`_ms_seeded`）是同一套道理。
- **文案**：天数「已经记了 10 天」；小时「累计 100 小时了」。不说「恭喜」也不放烟花（烟花是下班专属，别稀释）。
- **在岗时间的中位数**（面板里的「常在」）也归在这一项：`typical_start()` 取最近 30 天到岗分钟数的中位数，抗偶发的 06:00 与 10:30。

### P2 · v1.2 流年

**主题：让这块地跟着时间走。** 不是回看数据，是让世界本身有年岁——草色、花色、天色、声音都随季节换。

顺序是按依赖排的：季节是地基，雪挂在它上面；音效和互动随时能加，不动画面结构。

| 顺序 | 件 | 做什么 | 目标情绪 |
|---|---|---|---|
| 1 | **F12 季节换装** | 春 2–4 樱粉、夏 5–7 浓绿、秋 8–11 橙黄、冬 12–1 冷灰。草色、花色、天色一起换；按日期**硬切**，不做渐变 | 时间在走，一眼看得见 |
| 2 | **F17 四季特效** | 冬下落雪（含顶栏积雪，厚度看天气）、**秋飘落叶**（橙黄两像素的小片，横向打着旋；雨雪天不飘）。都是季节常态，不是降水 | 雪是稀罕物、落叶是时间的脚步声。落叶位置按**屏幕像素**取整（不是按单位），速度差 1.5~5.5；**所有天气动画默认 60fps**，外观菜单里有高/中/低三档（60/30/15 帧）——老机器嫌费电可调低 |
| 2b | **F17 下雪** | 冬季专属：雪花慢飘、草地盖白顶。复用雨滴机制但更慢更轻，别做成雨。**顶栏那条草皮带也压雪**，厚度 3~6 单位、有起伏、下沿带冷灰影（1~2 单位会像画错的白边） | 雪是稀罕物，一年只有两个月 |
| 3 | **F14 音效** | 下班一声柔和音符、里程碑一声轻响，**默认关**，菜单里开 | 仪式感，两秒钟的事，但会让人抬头 |
| 4 | **F13 轻互动** | 点草地：以落点为圆心，**中心的花被顶开留出空洞、外圈的花向两侧推开并倒伏**，0.42 秒内按平方衰减归位。**要逐帧画**（16ms 定时器）——主窗口一秒才重绘一次，只设状态的话只会闪一帧；不拦拖动，位置挪过就不算点。**草地上双击也是推，不弹登记窗**（连点是这互动的乐趣所在，弹窗会打断；登记窗走右键菜单） | 从"看"变成"碰"，像一颗石子丢进水面 |

**几个已定的取舍**

- **冬天只留 12 月和 1 月**。按自然月算，冬天占四分之一，雪就不值钱了。缩到两个月，每年入冬像个事件。
- **硬切，不做渐变**。3 月 1 号一觉醒来世界变绿，这个"变"本身就是事件；渐变要多写一倍代码，还不一定看得出来。
- **四套底片必须一起做**。季节改的是所有颜色，现有 31 张基准图全部作废。按四季各生成一套（124 张，脚本自动跑），否则改完春天、到夏天才发现冬天的雪盖住了某个字。
- **F11 月度地图移出 v1.2**。日历年月做出来，每月 1 号打开是空白，得等一个月才好看。要做也是"最近 30 天滚动"，留到 v1.3 再看。
- **真实天气留到 v1.3（F18）**。现在的天气是按日期撒种子算出来的假天气；真天气要联网问，还要处理断网回退。

  三条硬规矩：
  1. **地点必须能手填**。按 IP 定位常错到省会——用户在某某市，报的是省会的天。自动定位只当默认值，手填永远能覆盖。
  2. **填错要认账**。设置页那一行必须写明「填错了，显示的就是别人那儿的天气」，不能让用户以为软件坏了。
  3. **不填就回退**。没填、填了查不到、断网——一律退回现在这套按日期撒种子的天气，画面不能空着。

  连带的好处：**积雪厚度看气温**。≤0℃ 厚雪、0~4℃ 薄雪、>4℃ 不积雪（暖冬就是没雪）。
  眼下没有真实气温，先用当天天气顶替：大雪 6 / 小雪 5 / 阴 3 / 晴 2 单位。

## 七、落地顺序建议

1. **先做 F1 + F3**（S 级，各半天的量）。这两项一上，产品性质就变了——从"计时器"变成"会说话的东西"，而且不新增任何数据。
2. **再做 F2 + F5 + F4**（S 级）。补满"事件"，P0 收口——这一步就是现在的 **v1.0**。
3. **F6 小生物**先做（S 级），它是陪伴感的性价比之王；F7 天气（M 级）看 F6 的反应再决定。
4. **F8 / F9 / F10**（M 级）进 **v1.1**，开始积累长期数据。
5. **F10 及 P2** 视 `interactions` 数据决定——如果一周里主动交互次数 < 1 次/天，说明该往"更安静"走，而不是加更多功能。

## 八、怎么判断做对了

- 一周内至少有 3 天，你会**主动**看它一眼（不是瞥时间，是等那个瞬间）。
- 出现"想关掉"的瞬间 = 失败：说明动效太长、太频繁或太亮。
- 把 `fx` 全部关掉后，界面与今天完全一致——说明特效是叠加的，不是嵌进主逻辑的。
- `interactions` 统计里，点击/菜单次数稳中有升，而不是装完两天后归零。

## 九、明确不做的事

| 不做 | 原因 |
|---|---|
| 番茄钟 / 待办清单 | 越界。它一旦能管理任务，就会变成"又一个要维护的工具"，快乐立刻变成负担 |
| 久坐提醒 / 喝水弹窗 | 打断式提醒在下班倒计时旁边只会加倍焦虑 |
| 社交 / 排行榜 / 同事工时对比 | 上班场景的攀比会反噬，且涉及隐私 |
| 复杂 3D、粒子光效、动图资源 | 破坏「1 单位 = 1 像素」的视觉语言，也会让 exe 变大、掉帧 |
| 大段文本（日志、感悟、AI 生成内容） | 一秒可读原则。每日一句的容量已经是上限 |
